# 功能测试目录说明

本目录用于存放 **功能性验证** 的测试用例（非特定历史 bug 回归）。

## 目标
- 验证核心玩法与系统功能在当前版本下按预期工作。
- 覆盖主要用户路径（点击、购买、资源流转、系统面板交互）。
- 为回归测试提供稳定的功能基线。

## 建议分层
- **core/**：核心机制（点击、购买、基础状态更新）
- **resources/**：资源生产/合成/分类展示
- **systems/**：科技、工人、住房、生命周期等系统流
- **ui/**：标签页、面板、响应式、视觉样式
- **performance/**：性能与压力验证

> 当前目录暂采用扁平结构；后续可按以上分层逐步迁移。

## 编写约定
- 文件命名：`<feature>.test.js`
- 每个用例应描述“功能目标 + 预期行为”，避免绑定一次性调试细节。
- 若测试用于复现历史缺陷，应迁移到 `tests/regression/`。

## 常用命令
- 跑全部功能测试：
  - `npx playwright test tests/functional --project=chromium`
- 跑全量测试：
  - `npm run test`
