# Idle Game 设计文档

## 1. 概述

### 1.1 项目目标
Rust + WebAssembly 闲置游戏，具有以下核心特性：
- **多资源系统**：金币、木头、石头等多种资源
- **点击收益**：前期手动点击获得金币
- **自动生产**：建筑提供自动资源生产
- **多语言支持**：简体中文（主语言）和英语
- **跨浏览器兼容**：支持 Chromium、Firefox、Webkit

### 1.2 技术架构
- **后端逻辑**：Rust WASM（高性能计算）
- **前端界面**：JavaScript + HTML + CSS（响应式UI）
- **数据流**：单向数据流，Rust 为唯一数据源

## 1.3 当前版本的设计目标（阶段化重构）

当前设计以“明确阶段 + 解锁衔接 + 隐藏发现”为主轴，后续代码改动必须围绕这一目标实现，而不是继续扩展平铺式内容。

### 1.3.1 五个核心阶段

| 阶段 | 玩家感受 | 核心玩法 | 代表内容 |
|------|----------|----------|----------|
| 阶段 1：初始阶段 | 只有点击和基础建筑 | 手动点击、购买最初几座建筑、建立食物前的原始经济 | 金币、木头、石头、基础建筑 |
| 阶段 2：工人阶段 | 资源开始依赖人口与供养 | 住房、工人分配、食物维持、效率提升 | 工人、住房、农场、基础工业科技 |
| 阶段 3：隐藏蛆虫阶段 | 死亡与腐化成为新的生产线 | 尸体衰变、蛆虫资源、黑暗生物科技分支 | 尸体、蛆虫、腐化建筑、隐藏科技 |
| 阶段 4：蛆虫人阶段 | 人类与蛆虫体系被迫共存 | 混合人口、共生稳定度、阵营拉扯、风险与收益并存 | 蛆虫人、共生建筑、宿主科技 |
| 阶段 5：集体意识阶段 | 生物科技与宇宙探索融合 | 集体意识、黑暗高科技、深空扩张、终局资源网络 | 暗物质、纳米机器、太空建筑、意识科技 |

### 1.3.2 阶段衔接原则

1. 每个阶段都必须通过解锁系统衔接，而不是直接在一开始全部展示。
2. 阶段推进由 Rust 侧统一判断，前端只展示“已揭示”的结果。
3. 旧资源、旧建筑、旧科技必须重新分布到各阶段，不允许继续无差别铺开。
4. 新增的黑暗科幻内容必须优先落在阶段 3-5，而不是挤占前期节奏。

### 1.3.3 隐藏内容展示规则

这是本轮重构的硬性要求：

1. **未解锁内容不得展示。**
2. **未揭示内容不得展示名字。**
3. **解锁列表本身也不能泄露未来内容。**
4. 某些阶段可以先“揭示存在”，再显示具体名称；在揭示前只能完全不出现，不能出现问号卡片、占位名或灰色条目。

| 内容类型 | 未揭示时 | 已揭示但未完成时 | 已解锁后 |
|----------|----------|------------------|----------|
| 阶段 | 不出现 | 出现在解锁/进度区域，显示正式名称 | 成为当前或已完成阶段 |
| 建筑 | 不出现在建筑列表 | 可见且可查看成本/条件 | 可购买 |
| 科技 | 不出现在科技树 | 可见依赖与成本 | 可研究/已研究 |
| 解锁条目 | 不出现 | 可显示标题与条件 | 标记为已完成 |

### 1.3.4 隐藏蛆虫阶段的特殊要求

蛆虫阶段不是普通公开阶段，而是“被发现”的阶段：

1. 玩家先经历工人饥饿、死亡与尸体积累。
2. 当尸体开始转化为蛆虫，系统才允许揭示这一条分支。
3. 在揭示之前，UI 中不能提前出现“蛆虫”“蛆虫人”等名称。
4. 揭示后再开放对应的建筑、科技和共生系统。

#### 1.3.4.1 生命周期异常前兆

蛆虫阶段的出现不能只依赖数值达标后突然切换，而必须通过生命周期系统逐步制造不安感，让玩家先感知“聚落出了问题”，再发现新的资源链。

前兆设计目标：

1. 让玩家在正式揭示前感到环境正在恶化。
2. 让饥饿、死亡、尸体积累与后续黑暗分支形成因果关系。
3. 在不泄露正式名称的前提下，为阶段 3 做情绪与信息铺垫。

前兆必须遵守以下规则：

1. 未揭示前不得出现正式资源名、阶段名、建筑名。
2. 前兆文本只能描述现象，不能直接解释机制。
3. 前兆强度必须随状态恶化分层提升，而不是只弹一次固定提示。
4. 前兆由 Rust 统一判断，前端只渲染当前异常等级与文本。

#### 1.3.4.2 异常等级分层

生命周期异常至少分为 3 个层级：

1. `warning`：出现持续饥饿、生产停滞、气氛异常等早期征兆。
2. `decay`：出现死亡、尸体滞留、聚落秩序恶化等中期征兆。
3. `breach`：尸体开始发生不可逆变化，即将触发正式揭示。

每一层都必须满足以下要求：

1. 有独立的触发条件。
2. 有独立的文案池，避免每次都重复同一句提示。
3. 可以在生命周期面板、解锁面板或顶部监视区出现，但内容必须一致。

推荐的异常描述方向：

- `warning`：空气变差、工人情绪不稳、食物系统失衡。
- `decay`：死亡增加、尸体处理压力上升、聚落出现腐败迹象。
- `breach`：尸体发生异动、腐化开始具备资源属性，但仍不说出正式名称。

#### 1.3.4.3 事件与日志系统

为了把生命周期异常从“状态数字”提升到“被玩家感知到的社会事件”，游戏必须新增一套可扩展的事件与日志系统。该系统既承担叙事反馈，也承担节奏修正，尤其要解决“食物长期充足导致尸体/蛆虫不足、进度被卡住”的问题。

事件系统目标：

1. 用新闻报道、紧急快讯与访谈形式，把聚落变化包装成持续发生的社会现实。
2. 让玩家在不切到生命周期面板时，也能通过顶部滚动提醒意识到风险正在累积。
3. 把关键阶段（工人、腐化、共生、集体意识）的变化写成可回看的历史记录，而不是瞬间飘过的提示。
4. 在不破坏主循环的前提下，为黑暗分支提供低频但可靠的“异常推进”修正。

##### 1.3.4.3.1 UI 结构要求

事件与日志系统必须包含以下界面结构：

1. `Header` 高度必须压缩，避免顶部信息层过高占用可视空间。
2. `Header` 下方必须新增一条横向滚动的紧急事件提醒栏，用于展示最近的高优先级事件标题。
3. 标签页必须新增 `日志` / `Logs` 面板，用于查看事件历史。
4. 日志面板必须按时间倒序展示条目，并允许玩家看到标题、正文、采访工人及其观点。
5. 日志条目必须限制总数，当前上限固定为 `1000` 条；超过后删除最旧条目，避免内存持续增长。
6. 日志视觉风格应接近新闻网站：最新稿件置顶，旧稿件自然向下沉降。
7. 日志正文必须按视口懒加载：卡片滚动到可见区域附近时，前端再向 Rust 请求该条新闻的完整拼装结果。

##### 1.3.4.3.2 事件模板与扩展性要求

事件系统不能写成只适配几十条硬编码文本的一次性结构，必须以“事件目录 + 组合式模板”的方式实现，保证未来可以从 `60` 个基础事件平滑扩展到 `600` 个基础事件而无需推翻架构。

实现要求：

1. 基础事件必须是可注册、可扩展的数据条目，而不是散落在多个文件中的临时 `if/else` 文案。
2. 每个基础事件必须支持约 `100` 种新闻报道变体，优先通过“标题模板 + 正文段落池 + 结尾池”的组合方式生成，而不是手写 100 篇固定报道。
3. 事件系统必须允许未来按类别、阶段、触发器、严重度进行扩容，而不要求重写前端渲染结构。
4. 文本生成必须同时支持中文与英文，但中文是主设计语言。
5. 事件文本库必须按阶段拆分；前一阶段事件与未解锁科技依赖事件不能在当前阶段触发。
6. 前端只加载已发生事件的日志正文，不加载全量候选事件模板；顶部提醒栏只拉取最近少量标题。
7. 已发生事件在存档中优先保存模板编号、阶段编号、变体编号、工人姓名/特性与必要快照数据，正文在展示时再现场拼接生成。

推荐的一级事件分类：

1. `生存危机 / Survival Crisis`
2. `黑暗转化 / Dark Conversion`
3. `工业进展 / Industrial Progress`
4. `社会异变 / Social Mutation`
5. `终局征兆 / Endgame Sign`

##### 1.3.4.3.3 事件效果比例与节奏职责

事件不能全部都带数值效果，否则系统会变成噪音式随机奖惩；但也不能全部都是纯文本，否则无法缓解节奏卡点。

当前设计比例固定为：

1. 约 `4:1` 的事件比率为“无实际数值效果的报道事件”对“有真实数值效果的异常事件”。
2. 大多数事件只负责氛围、预警、社会反馈与历史记录。
3. 少数有效果事件负责对停滞节奏进行轻量修正，例如：
   - 在食物过剩但尸体不足时制造低频异常死亡/尸体来源。
   - 在尸体资源极低时制造腐化副产物或幼体异动，帮助黑暗分支启动。
   - 在中后期为蛆虫、共生、意识相关分支制造新闻化的异常推进。
4. 有效果事件必须低频、可解释、与新闻内容一致，不能让玩家感觉只是后台偷偷发资源。

##### 1.3.4.3.4 工人采访与人格表达

每条事件在生成时，都必须尽量绑定一名随机工人作为被采访者，并根据该工人的特性生成观点文本。

要求如下：

1. 事件正文中的人物必须优先使用真实工人姓名。
2. 工人观点必须根据特性生成，而不是所有工人都说同一种话。
3. 至少要覆盖以下人格方向：
   - 勤奋/高效/坚持型
   - 懒惰/缓慢/粗心型
   - 聪明/快速学习/创意型
   - 社交/魅力/乐观型
   - 孤僻/害羞型
   - 夜猫子/早起者等作息型
4. 工人评论必须能与事件主题呼应，而不是独立于上下文的随机句子。

##### 1.3.4.3.5 报道风格要求

事件文本风格参考中国与美国新闻报道，但不能完全复刻现实媒体模板，而应形成“聚落媒体生态”的混合风格。

写作要求：

1. 中文稿件允许使用 `【本台讯】`、`【深度报道】`、`【产业前沿】` 等栏目口吻。
2. 英文稿件允许使用 `Breaking Desk`、`Metro Wire`、`Industry Brief`、`Field Dispatch` 等新闻化风格。
3. 报道内容必须强调：
   - 现场观察
   - 管理方口径
   - 数据或监测读数
   - 受访工人观点
4. 事件文本要让玩家感到“世界在持续运转”，而不是只看到系统提示框。

### 1.3.5 阶段总路线图

下表用于汇总整条主线的阶段目标、主瓶颈、关键解锁和下一阶段入口。后续实现、测试与调参都应优先对照这张路线图，而不是只看局部系统。

| 阶段 | 主目标 | 主瓶颈 | 关键解锁 | 下一阶段入口 |
|------|--------|--------|----------|--------------|
| 初始阶段 | 建立点击与基础资源循环 | 金币获取速度、第一批基础建筑 | 基础资源建筑、解锁面板入口 | 购买足够基础建筑，进入工人阶段 |
| 工人阶段 | 建立食物、住房、工人分配闭环 | 食物供养、工人效率、首批科技 | 农场、住房、工人系统、基础工业科技 | 饥饿、死亡、尸体与异常等级推动隐藏分支出现 |
| 蛆虫阶段 | 理解尸体/蛆虫的黑暗生产链 | 尸体转化效率、首批黑暗科技与建筑 | 蛆虫资源、蛆虫工厂、黑暗转化科技 | 黑暗资源链稳定后，开始宿主与共生过渡 |
| 蛆虫人阶段 | 管理混合人口与共生稳定 | 人类压力、蛆虫影响、共生稳定度 | 共生建筑、混合人口、宿主科技 | 统一意识前置条件满足，进入终局整合阶段 |
| 集体意识阶段 | 把所有资源链整合为文明级扩张网络 | 高阶资源网络、终局科技与星际扩张效率 | 意识科技、太空建筑、终局资源链 | 进入终局闭环与最终扩张目标 |

阶段路线约束：

1. 每个阶段都必须教会玩家一个新的主系统。
2. 每个阶段都必须保留前一阶段的资源与逻辑价值，不能把旧系统彻底作废。
3. 下一阶段入口必须来自当前阶段的后果或深化，而不是凭空跳转。
4. 目标链、科技、建筑揭示与数值平衡都必须服从这张总路线图。

## 1.4 阶段资源与建筑分布原则

### 1.4.1 初始阶段
- 仅保留最基础的点击与生存型资源：金币、木头、石头。
- 仅展示最早期建筑，不出现黑暗科技和高级工业名词。

### 1.4.2 工人阶段
- 引入食物、住房、工人效率。
- 前期工业资源从这一阶段开始逐步出现，但必须由工人与食物链支撑。

#### 1.4.2.1 工人阶段的承接目标

工人阶段不能只通过“突然出现更多标签页”来表达扩展，而必须通过连续的小目标把玩家从点击经济平滑带入人口与供养系统。

进入工人阶段后，系统必须满足以下体验要求：

1. 玩家在 5 秒内能看懂当前唯一主目标。
2. 玩家在 30 秒内至少能完成 1 个新目标。
3. 新阶段必须给出即时奖励感，不能只增加管理负担。
4. 工人系统必须尽快从“展示信息”变成“要求玩家做选择”。

#### 1.4.2.2 工人阶段目标链

工人阶段采用线性目标链，而不是并行开放全部系统。第一期目标链固定为以下顺序：

1. 建造第一座农场。
2. 获得第一份食物。
3. 分配第一名工人。
4. 研究第一项基础科技。

目标链规则：

1. 同时只激活 1 个主目标。
2. 每一步都必须显示进度、奖励与推荐操作方向。
3. 每一步完成后立即切换到下一步，不能要求玩家自己猜测后续目标。
4. 目标链状态必须可持久化，并在读档后继续保持。

#### 1.4.2.3 阶段奖励包

工人阶段解锁时必须发放一次性奖励包，用于提供“第一脚油门”，避免玩家刚进入新系统就因资源断档而停滞。

当前默认奖励方案：

- `Food +10`
- `Gold +30`

奖励包规则：

1. 每个阶段奖励只能发放一次。
2. 奖励必须足够推动下一步目标，但不能直接跳过该阶段的核心玩法。
3. 奖励状态必须写入存档，避免重复领取。

#### 1.4.2.4 工人系统的决策深度

工人阶段的重点不是“拥有工人”，而是“如何使用工人”。因此工人属性必须真实接入产能计算，而不能只停留在展示层。

第一期必须生效的决策因素：

1. 偏好岗位匹配：提供稳定正向效率加成。
2. 饥饿状态：提供明显负向效率修正。
3. 心情状态：提供轻量但可感知的效率波动。

实现要求：

1. 工人卡片必须显示当前效率来源。
2. 工作总览必须显示岗位层面的平均效率与分配率。
3. 玩家在不同分配选择之间必须能感知明确优劣，而不是只有数值暗改。

#### 1.4.2.4.1 自动分配规则

`AutoAssignment` 解锁后，自动分配工人不能只是随机填满空位，而必须优先选择当前收益最大的岗位。

自动分配规则：

1. 系统必须基于当前可分配岗位的预期收益进行排序。
2. 预期收益至少要考虑建筑基础产出、工人偏好、当前效率修正与关键负面状态。
3. 自动分配的默认目标是最大化当前总产出，而不是平均分配人口。
4. 若多个岗位收益相同，才允许使用稳定的次级规则打破平局。

设计要求：

1. 自动分配结果必须与手动分配的收益逻辑一致。
2. 玩家应能在工人卡片或工作总览中看出自动分配为何选择该岗位。
3. 自动分配是效率工具，不应绕过食物、住房、稳定度等系统压力。

#### 1.4.2.5 工人阶段的揭示节奏

工人阶段解锁后，可以揭示更多系统，但不能一次性把全部复杂度压到玩家身上。

揭示策略要求：

1. 优先引导玩家使用与当前目标直接相关的面板。
2. 非关键面板可以先显示入口，但必须通过目标、高亮或描述告诉玩家当前优先级。
3. 科技、住房、工作总览、生命周期等系统的首次接触应围绕“食物 -> 劳动 -> 生存压力”这一主线组织。

#### 1.4.2.6 目标链 UI 与反馈交互规范

目标链不是隐藏在系统深处的文字说明，而是工人阶段最重要的前端引导层。玩家必须在主界面上持续看到“当前要做什么、做完能得到什么、接下来该去哪里”。

目标链 UI 的布局要求：

1. 目标面板必须位于主界面高可见区域，优先放在顶部资源横幅下方或主内容区顶部。
2. 面板默认只强调当前主目标，后续目标可以弱化显示或完全隐藏。
3. 目标面板在阶段未开启前不得占位显示，也不能提前透露后续内容。

目标面板至少包含以下信息：

1. 当前目标标题。
2. 一句话描述，告诉玩家为什么要做这件事。
3. 实时进度，例如 `0 / 1`。
4. 完成奖励。
5. 推荐前往的面板或操作方向。

#### 1.4.2.7 完成反馈与引导反馈

每个目标完成时，系统必须立即给玩家一个短、明确、正向的反馈，告诉玩家自己刚刚完成了什么，并把注意力转移到下一步。

完成反馈规则：

1. 反馈必须在目标完成后立即出现，不能要求玩家切换面板后才知道。
2. 反馈文本必须先说明“完成了什么”，再说明“下一步是什么”。
3. 反馈应简短，不打断主要操作节奏。

推荐反馈结构：

- `目标完成：建造第一座农场`
- `下一步：获得第一份食物`

当目标切换后，系统还必须提供轻量引导反馈：

1. 若下一步与特定面板强相关，对应 tab 需要出现一次性高亮。
2. 高亮是提示，不是强制跳转；玩家仍可自由操作。
3. 同一目标的高亮不应无限重复闪烁，避免造成噪音。

#### 1.4.2.8 目标链与标签页联动规则

目标链必须决定“当前优先看什么”，而不是单纯给出文本。标签页、解锁面板与顶部监视区都应服务于这一引导逻辑。

联动规则：

1. `build_farm` 阶段优先引导到建筑面板。
2. `gain_food` 阶段优先引导到资源面板或工作总览。
3. `assign_worker` 阶段优先引导到工人面板。
4. `research_first_tech` 阶段优先引导到科技面板。

实现约束：

1. 引导信息必须和 Rust 返回的当前目标一致，前端不得自行猜测当前步骤。
2. 解锁面板中的说明文案必须和目标面板语义一致，避免一个说“建农场”，另一个说“发展农业”。
3. 同一时刻只能有一个高优先级引导目标，避免多个面板同时抢注意力。

#### 1.4.2.9 视觉与信息密度原则

工人阶段的引导 UI 必须帮助玩家减压，而不是再制造新的阅读负担。

因此必须满足以下原则：

1. 当前目标信息必须在 1 次扫视内读完。
2. 不使用大段说明文本替代状态与进度。
3. 重要性顺序固定为：当前目标 > 进度 > 奖励 > 推荐面板 > 背景说明。
4. 反馈文案与前兆文案不能同时争夺最高视觉层级，避免主任务与氛围提示互相冲突。

#### 1.4.2.10 工人阶段的首批科技承接

工人阶段目标链的最后一步是“研究第一项基础科技”，因此科技系统在这一阶段不能只是一个独立面板，而必须成为建筑扩张与新生产线出现的正式入口。

工人阶段的首批科技承接目标：

1. 玩家进入工人阶段后，始终至少有 1 项可立即研究的基础科技。
2. 首批科技必须和当前目标链、资源链、建筑解锁直接相关。
3. 玩家研究后必须立刻看到新的建筑或明确产能变化，不能只获得抽象数值。

第一期推荐的工人阶段科技顺序：

1. `BasicAgriculture`：农业正式建制化，确认农场是工人阶段的核心供养建筑。
2. `BasicSmelting`：揭示金属加工入口，解锁冶炼相关建筑。
3. `BasicEngineering`：揭示基础工业装配入口，解锁工厂类建筑。

首批科技引导规则：

1. 目标链推进到 `research_first_tech` 时，科技面板必须优先推荐首个可研究科技。
2. 若玩家可研究多项科技，必须有一项被标记为当前推荐路线。
3. 推荐路线应优先服务于当前阶段主线，而不是鼓励玩家过早进入高阶工业分支。

### 1.4.3 蛆虫阶段
- 尸体与蛆虫从“后果”转变为“资源链”。
- 黑暗生物建筑与腐化型科技在此出现。

#### 1.4.3.1 蛆虫阶段的揭示方式

蛆虫阶段不能像普通阶段那样通过常规解锁卡直接出现，而必须从前兆升级为“发现事件”。

揭示流程要求：

1. 玩家先经历工人阶段的食物危机、死亡与尸体累积。
2. 生命周期异常等级提升到 `breach` 后，才允许触发正式揭示。
3. 正式揭示时，系统将此前的模糊异常重新解释为新的生产链入口。
4. 揭示后才允许展示蛆虫相关资源、建筑、科技和阶段名。

#### 1.4.3.2 触发条件设计原则

蛆虫阶段的触发条件必须来自玩家已体验过的系统后果，而不是脱离上下文的隐藏计数器。

第一期推荐触发条件组合：

1. 至少发生过一次工人死亡。
2. 尸体资源在场上累计到阈值。
3. 生命周期异常等级达到 `breach`。
4. 蛆虫资源首次生成后，才将阶段名写入已揭示内容。

触发条件应满足：

1. 玩家可以通过自己的行为间接影响其发生速度。
2. 玩家在事后能理解“为什么现在会进入这一阶段”。
3. 即使玩家未主动查看文档，也能从系统表现中读出因果链。

#### 1.4.3.3 揭示后的体验目标

蛆虫阶段的首次揭示必须让玩家产生“原来前面的异常不是背景装饰，而是新玩法前兆”的感受。

揭示后的短期体验目标：

1. 将死亡与尸体从纯惩罚转化为可利用但带风险的资源链。
2. 让玩家立刻看到新的选择，而不是只收到负面状态。
3. 让工人阶段的生存压力自然过渡到黑暗生产线，而不是硬切换到另一套系统。

#### 1.4.3.4 蛆虫阶段首次揭示后的短期目标链

蛆虫阶段被揭示后，系统不能只把新资源和新建筑丢给玩家，而必须像工人阶段一样提供一条清晰的短期目标链，帮助玩家理解黑暗生产线的最小闭环。

第一期的蛆虫阶段短期目标链推荐顺序：

1. 接受异常已经成为资源入口这一事实，查看新的生命周期说明。
2. 获得第一批蛆虫资源。
3. 建造第一座蛆虫相关建筑。
4. 完成第一次“尸体/蛆虫 -> 食物或化学品”的黑暗转化。
5. 研究第一项蛆虫科技。

该目标链的设计目标：

1. 让玩家在揭示后 30-60 秒内理解新的资源闭环。
2. 让玩家亲手完成一次从死亡后果到生产收益的转化。
3. 避免玩家只看到负面氛围，却不知道如何利用新系统。

#### 1.4.3.5 蛆虫阶段目标链的交互规则

蛆虫阶段的目标链必须和揭示事件强绑定，揭示完成后立即切换为新的主目标，不再继续显示工人阶段的末尾目标。

交互规则：

1. 蛆虫阶段一旦正式揭示，当前主目标必须切换到蛆虫阶段首个目标。
2. 目标文案必须明确告诉玩家“新的资源链已经出现”。
3. 每一步仍然只激活 1 个主目标，避免黑暗分支初见时信息过载。
4. 若当前目标关联生命周期、建筑、科技等不同面板，仍然采用单一高优先级引导原则。

推荐的步骤联动：

1. `inspect_decay`：优先引导生命周期面板。
2. `gain_maggot`：优先引导资源面板或生命周期面板。
3. `build_maggot_facility`：优先引导建筑面板。
4. `complete_dark_conversion`：优先引导工作总览或资源面板。
5. `research_maggot_tech`：优先引导科技面板。

#### 1.4.3.6 揭示后的首批建筑与科技承接

蛆虫阶段首次揭示后，不应一次性开放全部黑暗内容，而应只开放最小可理解集合。

第一期推荐的首批承接内容：

1. 基础蛆虫资源可见。
2. `蛆虫工厂` 作为第一座黑暗转化建筑。
3. 第一项蛆虫科技用于稳定或强化初始黑暗生产线。

承接原则：

1. 首批建筑必须足以让玩家完成一次黑暗转化。
2. 首批科技必须直接强化刚刚接触到的蛆虫链，而不是跳到更远的共生终局内容。
3. `腐肉育池`、`共生培育舱` 等更进一步的内容应在玩家完成第一轮黑暗闭环后再继续揭示。

#### 1.4.3.7 蛆虫阶段的体验边界

蛆虫阶段的首轮体验应当阴森、反常，但仍然要可理解、可操作，不能把玩家推入纯惩罚状态。

因此必须满足以下边界：

1. 黑暗资源链必须提供可见收益，不能只有氛围和风险。
2. 玩家第一次接触蛆虫阶段时，不应被要求同时理解蛆虫、宿主、蜂巢、集体意识等全部远期概念。
3. 首次揭示后的 2-3 个目标只服务于“理解新资源链”这一件事。
4. 真正复杂的共生数值与阵营拉扯，必须延后到蛆虫人阶段再成为主线。

#### 1.4.3.8 工人阶段到蛆虫阶段的数值节奏目标

工人阶段到蛆虫阶段的过渡不能靠纯随机事故或突然崩盘来触发，而必须是一段可感知、可干预、可理解的压力升级过程。

这一段节奏必须同时满足：

1. 玩家能先体验到“维持供养体系”的正常玩法。
2. 玩家会逐步感受到食物、住房、分配与死亡之间的真实压力。
3. 玩家如果连续忽视这些压力，就会自然进入黑暗分支。
4. 玩家即使进入黑暗分支，也不应因为一次失误直接陷入不可恢复状态。

#### 1.4.3.9 过渡阶段的卡点控制原则

工人阶段到蛆虫阶段之间必须允许卡点，但这些卡点应当是“提示玩家换策略”的设计，而不是“资源断粮后什么都做不了”的死锁。

卡点控制规则：

1. 卡点只能迫使玩家调整建筑、分配、科技或供养策略，不能让玩家失去全部可行动作。
2. 关键卡点前必须有预警，包括目标提示、异常文本、效率下降或面板反馈。
3. 卡点后的恢复路径必须清晰，玩家应能判断自己是缺食物、缺工人、缺住房还是缺科技。
4. 蛆虫阶段揭示前的死亡压力应当是“可逆的失败边缘”，而不是彻底失败结局。

#### 1.4.3.10 资源压力的递进顺序

工人阶段到蛆虫阶段的压力递进应遵循固定顺序，而不是所有问题同时爆发。

推荐的压力递进顺序：

1. 玩家先感受到食物供给不足，工人效率开始下降。
2. 随后出现空闲工人、低效率工人或分配不合理带来的产能停滞。
3. 再后出现饥饿、死亡与尸体积压，异常等级开始抬升。
4. 最终才由尸体与蛆虫资源把压力转化为新的生产链入口。

这样可以保证：

1. 玩家先理解普通生存系统，再理解黑暗分支。
2. 前期失败的因果链条清晰，不会显得突兀。
3. 黑暗分支像是对旧系统后果的再利用，而不是凭空出现的新玩法。

#### 1.4.3.11 关键资源的软硬门槛

工人阶段到蛆虫阶段之间，必须区分“软门槛”和“硬门槛”。

软门槛：

1. 食物不足导致效率下降。
2. 心情下降导致产能波动。
3. 分配错误导致推进变慢。

硬门槛：

1. 没有基础住房时，人口无法持续增长。
2. 没有基础食物来源时，工人系统无法稳定运转。
3. 没有首批关键科技时，工业建筑不得揭示。

设计要求：

1. 软门槛用于制造选择压力。
2. 硬门槛用于控制阶段顺序。
3. 任何一次关键进度推进都不应同时依赖 3 个以上硬门槛，避免玩家无法判断被什么卡住。

#### 1.4.3.12 阶段奖励与恢复窗口

为了避免玩家在工人阶段末尾或蛆虫阶段初见时因为连续失误而彻底停摆，系统必须保留恢复窗口。

恢复窗口规则：

1. 工人阶段的奖励包必须足以支持玩家完成第一轮供养建制。
2. 蛆虫阶段首次揭示后，首批黑暗建筑或科技必须提供可见恢复能力。
3. 恢复窗口是“给玩家重新选择的机会”，不是直接跳过压力系统。
4. 恢复窗口只能缓解短期崩盘，不能永久消除生存压力。

#### 1.4.3.13 数值节奏的体验目标

工人阶段到蛆虫阶段之间的理想体验节奏应为：

1. 先建立秩序。
2. 再出现压力。
3. 然后感知失控。
4. 最后把失控重新组织成新的生产力。

这一段节奏的核心不是单纯提高难度，而是让玩家感到自己正在从“维持聚落”过渡到“利用聚落的崩坏后果”。

#### 1.4.3.14 蛆虫科技树的首批路线

蛆虫阶段的科技路线必须服务于“先理解黑暗资源链，再扩展到共生体系”的目标，不能一揭示就把玩家直接推到宿主、蜂巢或集体意识层面。

第一期推荐路线：

1. `MaggotBreeding`：确认蛆虫资源链是可持续生产线，而不是一次性事故收益。
2. `NecroticRecycling`：把坏死资源重新并入食物或化学循环，建立第一轮黑暗转化闭环。
3. `SymbioticHosts`：在玩家已经掌握蛆虫链基础后，再进入共生阶段的前置概念。

路线原则：

1. 首项科技必须直接强化玩家刚刚接触到的资源。
2. 第二项科技必须把黑暗资源链与主生产链重新接上。
3. 第三项科技才允许开始引入“人类与蛆虫共生”这一更复杂的主题。

#### 1.4.3.15 蛆虫建筑与科技映射

蛆虫阶段的建筑同样必须随着科技逐步揭示，不能在阶段揭示瞬间全部出现。

第一期推荐映射：

| 科技 | 解锁建筑 | 作用 | 阶段定位 |
|------|----------|------|----------|
| `MaggotBreeding` | `蛆虫工厂` | 让蛆虫资源进入稳定生产 | 阶段揭示后的第一座核心建筑 |
| `NecroticRecycling` | `腐肉育池` | 将尸体/坏死组织重新并入食物或化学链 | 第一轮黑暗闭环扩展 |
| `SymbioticHosts` | `共生培育舱` | 把黑暗链条过渡到宿主与共生系统 | 通往蛆虫人阶段的桥梁 |

映射要求：

1. 每一项蛆虫科技必须明确揭示对应建筑或明确强化现有黑暗建筑。
2. 首次接触阶段不允许同时出现 3 座以上新黑暗建筑。
3. 后续建筑必须以“先处理尸体和蛆虫，再处理宿主和共生”为顺序揭示。

#### 1.4.3.16 蛆虫科技的面板引导规则

蛆虫科技的科技面板必须比普通工业科技更强调“它会打开什么黑暗操作路径”，避免玩家只看到抽象词汇而无法理解用途。

引导要求：

1. 科技详情必须写明它会揭示哪座黑暗建筑。
2. 科技详情必须写明它改变的是哪一段资源链，例如“尸体 -> 蛆虫”或“坏死组织 -> 食物”。
3. 研究完成后，建筑面板或生命周期面板必须给出对应反馈。

#### 1.4.3.17 蛆虫路线与共生路线的分层

蛆虫阶段的首批科技路线只负责建立黑暗生产力，不负责完整展开共生政治、混合人口与集体意识。

分层要求：

1. `MaggotBreeding` 与 `NecroticRecycling` 属于黑暗资源工业层。
2. `SymbioticHosts` 才是从黑暗资源工业层进入共生社会层的入口。
3. `HiveMindProtocol` 与 `CollectiveAwakening` 必须严格后置，不得在玩家尚未理解宿主系统时提前进入主线。

### 1.4.4 蛆虫人阶段
- 不再只靠单纯人类工人生产。
- 系统要允许混合人口产生收益与风险。

#### 1.4.4.1 蛆虫人阶段的核心循环

蛆虫人阶段不是单纯把“蛆虫资源再做大”，而是把黑暗资源链推进为人口结构变化与社会结构变化。这个阶段的核心循环必须从“处理尸体”升级为“管理共生人口”。

第一期核心循环应为：

1. 通过蛆虫科技与黑暗建筑稳定获得蛆虫资源。
2. 将部分人类人口转入宿主/混合人口链。
3. 混合人口提供新的高风险高收益产能。
4. 共生数值波动反过来影响传统人类系统与黑暗系统。
5. 玩家持续在扩张收益与失稳风险之间做选择。

#### 1.4.4.2 该阶段的玩家问题

蛆虫人阶段必须围绕一个明确问题展开：

`你是否愿意用更高的社会风险，换取更强的生产力与更快的阶段推进？`

因此这个阶段的玩法不能只是“继续造新建筑”，而必须让玩家不断权衡：

1. 保守维持人类秩序，降低风险但推进较慢。
2. 加速转化混合人口，提升产能但推高社会压力与失稳概率。

#### 1.4.4.3 核心数值如何进入玩法

共生数值系统在蛆虫人阶段必须正式成为主玩法，而不再只是背景状态。

四项核心指标在该阶段的主要职责：

1. `人类压力`：代表传统社会对异化扩张的反弹，过高时压制黑暗产能并制造秩序成本。
2. `蛆虫影响`：代表腐化生态对整个生产系统的渗透，过高时会侵蚀传统建筑与人口稳定性。
3. `共生稳定度`：代表两套体系是否还能共存，是该阶段最重要的持续性指标。
4. `混合人口`：代表已经完成转化并参与生产的核心新劳动力，是阶段推进的关键正向资源。

玩法要求：

1. 这四项指标必须同时可见，并且彼此影响。
2. 这些指标必须真正影响产能、建筑效率、事件风险与后续解锁。
3. 玩家必须能通过建筑、科技、分配策略主动调节它们，而不是只能被动承受。

#### 1.4.4.4 蛆虫人阶段的最小目标链

蛆虫人阶段首次进入后，也必须有一条清晰的短期目标链，帮助玩家理解“共生”不是纯背景设定，而是新的生产与风险管理层。

第一期推荐顺序：

1. 获得第一批混合人口。
2. 建造第一座共生建筑。
3. 让混合人口第一次参与生产。
4. 将共生稳定度维持在安全区间内完成一个短周期运转。
5. 研究第一项蛆虫人阶段科技。

#### 1.4.4.5 产能与风险的交换原则

蛆虫人阶段的设计关键是“交换”，而不是简单地把所有新单位做得更强。

交换原则：

1. 混合人口的单位产能可以高于普通工人。
2. 但混合人口扩张必须显著推高 `人类压力` 与 `蛆虫影响`。
3. 若 `共生稳定度` 失控，则高产能会转化为事故、衰退或压制效果。
4. 玩家必须能够看见并理解这种交换关系，不能只通过隐藏数值结算。

#### 1.4.4.6 蛆虫人阶段的建筑与科技方向

蛆虫人阶段的内容不应继续围绕“尸体处理”，而应转向“宿主培育、稳定控制、混合生产”。

建筑方向：

1. 宿主培养设施。
2. 共生稳定设施。
3. 混合人口专属生产设施。

科技方向：

1. 宿主控制。
2. 共生稳定。
3. 群体协调。

内容揭示顺序要求：

1. 先让玩家理解混合人口如何产生。
2. 再让玩家理解如何稳定维持混合人口。
3. 最后才让玩家把混合人口扩展到更宏观的社会级或意识级系统。

#### 1.4.4.7 蛆虫人阶段的失败边界

蛆虫人阶段必须允许高风险玩法，但不应因为一次数值波动就把整个存档打回纯惩罚状态。

失败边界要求：

1. 低稳定度应首先表现为效率下降、事件压力上升或部分系统受限。
2. 极端失稳可以触发严重后果，但必须给玩家留下恢复窗口。
3. 玩家在该阶段的失败应被理解为“共生秩序暂时失控”，而不是“游戏直接报废”。

### 1.4.5 集体意识阶段
- 高级资源、意识科技、太空探索集中在终局阶段。
- 暗物质、纳米机器、太空船等高阶内容必须与前面的黑暗生物链条相连。

#### 1.4.5.1 集体意识阶段的核心定位

集体意识阶段是整条主线的终局整合阶段。它不再只是“再造更大的建筑”，而是把前面所有阶段建立的人类、黑暗、共生、工业与高科技资源网络压缩为一个统一意识驱动的超级生产体系。

该阶段的核心问题是：

`当个体差异被汇入统一意识后，你要如何把整个文明改造成一台跨星际扩张机器？`

#### 1.4.5.2 终局核心循环

集体意识阶段的核心循环必须从“管理个体与群体矛盾”升级为“管理统一意识的扩张效率与文明尺度资源网络”。

第一期终局循环推荐为：

1. 通过共生稳定与混合人口积累进入统一意识前置条件。
2. 将高阶资源链整合为意识科技、能源科技与星际建造链。
3. 生产终局资源，例如暗物质、纳米机器、时间水晶、太空船。
4. 通过意识类科技与太空设施扩大整体文明尺度产能。
5. 用终局网络反过来重塑低阶资源链，使前期资源也成为高阶扩张的一部分。

#### 1.4.5.3 终局资源网络原则

终局资源不能是彼此孤立的“高级材料列表”，而必须组成一张可追溯来源的资源网络。

资源网络要求：

1. 暗物质必须与黑暗链和共生链有关，不能凭空出现。
2. 纳米机器必须与高科技工业链和意识科技链有关。
3. 太空船必须依赖能源、工业、意识协调与高阶材料共同支持。
4. 时间水晶、量子计算、反物质等资源必须承担“突破文明上限”的终局作用。

玩家应能清楚读出：

1. 低阶资源如何一路进入终局制造。
2. 黑暗分支如何在终局不再只是异端路线，而成为核心动力来源之一。
3. 共生系统如何从风险源演化为终局组织效率来源。

#### 1.4.5.4 集体意识阶段的最小目标链

集体意识阶段首次进入后，也需要一条短期目标链，让玩家理解终局系统不是单纯数值膨胀。

第一期推荐顺序：

1. 满足统一意识觉醒条件。
2. 建造第一座意识或星际级终局建筑。
3. 产出第一批终局资源。
4. 将终局资源接入一条现有工业或黑暗链。
5. 完成第一次文明尺度扩张操作。

#### 1.4.5.5 终局建筑方向

终局建筑应围绕“意识整合、文明放大、星际投射”三条线展开。

推荐方向：

1. 意识整合设施：用于提升统一意识效率与群体协调。
2. 高阶制造设施：用于生产纳米机器、量子计算资源、反物质等。
3. 星际扩张设施：用于生产太空船、深空孵化港、远征网络。

揭示顺序要求：

1. 先让玩家能产出第一批终局资源。
2. 再让玩家把终局资源接入文明尺度扩张。
3. 最后再开放真正改变胜利尺度或终局结算方式的建筑。

#### 1.4.5.6 终局科技方向

集体意识阶段的科技不能只是数值翻倍，而必须真正改变文明运作方式。

推荐方向：

1. `ConsciousnessUpload`：让个体生产转向统一意识协调。
2. `QuantumComputing` / `TimeManipulation`：提升整体文明级调度与时间效率。
3. `SpaceExploration` / `Terraforming`：把资源网络投射到星际层面。
4. `CollectiveAwakening` / `Omniscience`：作为终局认知层与全局信息层的最后展开。

#### 1.4.5.7 终局的胜利感来源

终局阶段的爽感不应来自单一数字暴涨，而应来自“你终于看见整张网络如何闭环”。

胜利感应来自：

1. 前期资源链在终局仍然有意义。
2. 黑暗路线与人类路线在终局不再互相排斥，而是被统一进同一文明机器。
3. 玩家能够明显感受到自己已经从“点击赚金币”走到“调度跨星际意识文明”。

## 1.5 共生数值系统目标

蛆虫人与人类的共存不能只靠一个简单计数器，而是至少包含以下四类状态：

| 指标 | 含义 | 作用 |
|------|------|------|
| 人类压力 | 人类社会对异化的排斥、恐慌与维稳压力 | 过高时压制黑暗分支效率 |
| 蛆虫影响 | 腐化生态对生产与人口系统的渗透程度 | 过高时侵蚀传统生产秩序 |
| 共生稳定度 | 人类与蛆虫人是否能维持脆弱平衡 | 决定阶段 4 是否可持续 |
| 混合人口 | 已完成转化并参与生产的蛆虫人数值 | 提供阶段 4-5 的关键产能 |

这些指标应满足以下目标：

1. 不能只增不减，要允许波动。
2. 要同时受资源、建筑、科技、饥饿/死亡等状态影响。
3. 要真正影响产能、风险和后续解锁。
4. 要为集体意识阶段提供前置条件。

## 1.6 前后端实现边界

1. 阶段判断、隐藏内容过滤、共生数值计算全部由 Rust 负责。
2. JS 只能请求“当前已揭示内容”和“当前已解锁内容”，不能自行猜测未来内容。
3. 前端渲染器必须接受“列表被过滤后长度变化”的情况，不能假设所有内容永远可见。
4. 保存与读档必须对新增阶段字段和共生字段保持向后兼容。

## 1.7 整体经济平衡原则

科技成本、建筑成本、食物压力和人口压力不能分别独立调参，而必须服务于同一条阶段推进主线。平衡设计的目标不是让每条数值单独“看起来合理”，而是让玩家始终知道自己为什么被卡、如何突破，以及突破后会进入什么新玩法。

### 1.7.1 平衡设计的总目标

整体经济平衡必须满足以下目标：

1. 每个阶段都存在一个清晰的主瓶颈。
2. 主瓶颈应推动玩家接触该阶段的核心系统。
3. 次要瓶颈可以制造选择压力，但不能掩盖主瓶颈。
4. 玩家突破当前主瓶颈后，必须能立刻感受到新的产能、面板或玩法变化。

### 1.7.2 建筑成本的职责

建筑成本的职责是控制“扩张速度”，而不是单纯拖慢节奏。

建筑成本设计原则：

1. 初级建筑成本负责鼓励快速建立第一轮资源循环。
2. 阶段关键建筑成本负责引导玩家优先处理当前主瓶颈。
3. 加工建筑与高级建筑成本负责限制玩家过早跳过中间资源链。
4. 建筑成本增长应让玩家感受到“该换系统了”，而不是“只能机械刷更多同类建筑”。

### 1.7.3 科技成本的职责

科技成本的职责是控制“系统揭示顺序”，不是单纯作为额外资源税。

科技成本设计原则：

1. 首批关键科技必须在玩家进入对应阶段后可在较短时间内研究完成。
2. 关键科技成本必须与对应资源链强关联，让玩家先体验资源准备，再体验内容揭示。
3. 科技成本不能高到让玩家在解锁目标链最后一步前长期停滞。
4. 若科技负责揭示建筑，则研究完成后的收益感必须足以抵消准备成本。

### 1.7.4 食物压力的职责

食物压力是工人阶段开始后的首个持续性维持成本，职责是迫使玩家从“只看增长”转向“增长与供养并重”。

食物压力设计原则：

1. 早期食物压力要足够真实，能让玩家感知供养系统的重要性。
2. 但早期食物压力不能过猛，避免玩家在刚接触工人系统时立刻崩盘。
3. 食物不足首先应该带来效率下降和预警，再逐步升级到死亡风险。
4. 食物系统必须始终和住房、分配、科技一起形成联动，而不是单独成为一个扣血条。

### 1.7.5 主瓶颈轮换原则

阶段推进中，主瓶颈应按系统教学顺序轮换，而不是所有压力同时维持最高强度。

推荐轮换顺序：

1. 初始阶段：点击效率与第一批基础建筑。
2. 工人阶段前段：食物与工人分配。
3. 工人阶段中段：首批科技与加工建筑揭示。
4. 工人阶段后段：住房、食物、死亡压力开始交错。
5. 蛆虫阶段：尸体与蛆虫资源链的转化效率。
6. 蛆虫人阶段：共生数值与混合人口稳定性。

### 1.7.6 软上限与换挡信号

当玩家长时间重复同一策略时，系统必须通过软上限告诉玩家“应该换挡”，而不是无限堆同一种最优解。

可接受的换挡信号包括：

1. 同类建筑边际收益下降。
2. 工人效率因供养或分配问题出现瓶颈。
3. 科技或建筑揭示需要新的中间资源链。
4. 食物、住房或稳定度开始压制纯产能扩张。

设计要求：

1. 软上限应让玩家换系统，而不是让玩家觉得被强行削弱。
2. 换挡信号必须通过 UI、目标链或面板信息明确表达。

### 1.7.7 建筑成本、科技成本与食物压力的协同规则

这三者必须协同工作，而不是分别制造卡点。

协同规则：

1. 当建筑成本提高时，科技应提供新的效率或建筑揭示作为突破口。
2. 当科技成本提高时，现有建筑链必须足以支持资源准备，不应要求玩家依赖尚未揭示内容。
3. 当食物压力提高时，玩家应能通过农场、分配、住房或科技找到明确缓解路径。
4. 任一时间点最多只有 1 个主压力源和 1-2 个辅助压力源，避免多重死锁。

### 1.7.8 恢复性平衡原则

经济系统必须允许玩家从错误策略中恢复，而不是一旦走偏就永久失去节奏。

恢复性平衡要求：

1. 错误建筑投资应当拖慢进度，但不应永久锁死主线。
2. 错误科技选择应当降低效率，但不应让玩家长时间没有可行下一步。
3. 食物崩盘应先制造警报、效率下降和局部损失，再进入严重后果。
4. 阶段奖励、首批科技收益和首批黑暗建筑都应承担部分恢复窗口职责。

## 3. 核心功能流程

### 3.1 点击流程
1. 用户点击中间区域
2. JavaScript 调用 `window.rustGame.click_action()`
3. Rust 更新 `coins += coins_per_click`
4. Rust 调用 `update_resources_only()` 更新UI
5. JavaScript 更新所有资源显示

### 3.2 购买流程
1. 用户点击购买按钮
2. JavaScript 调用 `buy_building(index)`
3. Rust 检查余额是否足够
4. **成功**：扣除资源，更新拥有数量，调用UI更新
5. **失败**：调用UI更新显示当前余额，提供视觉反馈

### 3.3 自动生产流程
1. 游戏循环每100ms执行一次
2. Rust 计算经过时间：`elapsed = (now - last_update_time) / 1000.0`
3. 更新各资源：`resource += resource_per_second * elapsed`
4. Rust 调用 `update_resources_only()` 更新UI

### 3.4 UI更新策略
- **增量更新**：避免不必要的DOM重绘
- **资源更新**：只更新资源数值，不重绘按钮
- **按钮更新**：只在购买成功时更新相关按钮
- **多语言支持**：所有文本通过i18n系统处理

### 9.1.3 科技效果类型

科技效果通过 `TechnologyEffect` 枚举定义：

```rust
pub enum TechnologyEffect {
    /// 生产加成：针对特定资源的产量加成 (如 +50% Gold)
    ProductionBonus(ResourceType, f64),
}
```

### 9.1.4 科技加成系统

`TechnologyBonuses` 结构体汇总所有已购买科技的效果：

```rust
pub struct TechnologyBonuses {
    /// 各类资源的生产加成倍率 (1.0 = 无加成)
    pub production_bonus: HashMap<ResourceType, f64>,
    /// 全局生产倍率 (1.0 = 无加成)
    pub production_multiplier: f64,
}
```

### 9.1.5 科技效果应用

科技加成在生产系统中自动应用。游戏主循环会计算科技加成，并将其传递给生产系统：

```rust
// idle_game.rs - game_loop
let tech_bonuses = self.technology_tree.calculate_bonuses();
let production = production::update_production(
    &self.buildings, 
    &self.workers, 
    &tech_bonuses
);
```

### 9.1.7 技术成本渲染规范

技术成本在 UI 中渲染时必须保持稳定的排序顺序，以避免每次面板刷新时资源顺序抖动。

#### 渲染一致性要求

1. **成本排序策略**：使用预定义的资源优先级列表对成本进行排序，确保相同的科技成本始终以相同顺序渲染。

2. **所有渲染路径一致**：技术成本排序逻辑必须在以下三个渲染位置统一应用：
   - 科技详情面板 (`renderTechDetail`)
   - 内联详情视图 (`selectTechnology` 备用路径)

3. **辅助方法**：在 `TechnologyManager` 中实现 `sortCosts` 辅助方法，接收成本对象并返回排序后的条目数组。

### 9.1.7.1 自动分配科技的行为约束

`AutoAssignment` 科技的效果不是单纯开启一个开关，而是开启“按当前收益最大化进行工人分配”的自动策略。

行为约束：

1. 自动分配必须优先把工人投向当前边际收益最高的岗位。
2. 收益评估必须复用正式产能计算逻辑，不能走独立的简化公式导致结果偏差。
3. 自动分配不得偷看未揭示建筑或未开放岗位。
4. 若后续引入混合人口或共生岗位，自动分配也必须继续遵守同一收益最大化原则。

### 9.1.9 建筑与科技的绑定规则

当前设计目标要求建筑不再以“全部初始化后逐步买得起”的方式出现，而必须随着阶段和科技共同揭示。也就是说，建筑的可见性与可购买性都必须由 Rust 侧统一判定。

这里的基本原则是：

1. 未达到所属阶段的建筑不得显示。
2. 达到阶段但未研究前置科技的建筑不得显示正式名称。
3. 研究完成后，建筑才允许进入建筑列表并可购买。
4. 建筑揭示必须让玩家理解“这座建筑为什么现在才出现”。

设计修正要求：

1. 不能继续让大批工业建筑从游戏开始就出现在运行时建筑池中。
2. `TechnologyEffect::UnlockBuilding` 必须从“仅有定义”升级为真实的显示与购买门控来源。
3. 同一类建筑的揭示应同时满足阶段条件与科技条件，避免科技树与阶段系统各说各话。

### 9.1.10 工人阶段的建筑解锁映射

工人阶段的建筑必须随基础科技逐步出现，推荐采用以下映射：

| 科技 | 解锁建筑 | 作用 | 备注 |
|------|----------|------|------|
| `BasicAgriculture` | `农场` | 稳定食物来源 | 工人阶段的第一座关键供养建筑 |
| `BasicSmelting` | `铁锭冶炼厂`、`铜锭冶炼厂` | 打开金属加工入口 | 仅在相关矿产已可见后揭示 |
| `BasicChemistry` | `化学品厂` | 打开化工支线 | 不应早于冶炼链过早出现 |
| `BasicEngineering` | `齿轮厂`、`钢铁厂` | 打开基础工业组件链 | 作为后续工厂体系的过渡 |
| `Electronics` | `电路板厂` | 打开电子工业 | 属于工人阶段后段或更后期 |

映射规则：

1. 科技解锁的是“建筑出现资格”，不是自动赠送建筑数量。
2. 若建筑依赖前置资源链，则必须保证上游建筑或资源已先被揭示。
3. 同一科技最多解锁一组主题一致的建筑，避免单次研究带来过多新内容。

### 9.1.11 科技面板与建筑揭示联动

科技研究完成后，玩家必须立刻感知到“有新建筑出现了”，而不是只看到科技状态变为已研究。

联动要求：

1. 研究完成后，建筑面板需要出现“新建筑已揭示”的反馈。
2. 若当前研究直接对应某个建筑链，建筑面板 tab 应获得一次性高亮。
3. 科技详情中应明确写出“将揭示哪些建筑”，避免玩家研究后仍不知道变化发生在哪里。

### 9.1.12 阶段化建筑池原则

建筑池必须从“全量静态列表”转为“按阶段和科技动态过滤后的已揭示列表”。

阶段化建筑池要求：

1. 初始阶段只保留点击经济与基础采集建筑。
2. 工人阶段优先揭示食物、初级加工、基础工业建筑。
3. 蛆虫阶段后才允许出现黑暗生物建筑与腐化建筑。
4. 集体意识阶段前不得出现终局太空或意识类建筑。

如果运行时仍保留全量建筑初始化，也必须在对外导出的建筑列表层做过滤；前端只能看到“当前已揭示的建筑”，不能直接看到未来建筑。

### 9.1.13 蛆虫科技树的首批路线映射

黑暗分支的科技路线必须与蛆虫阶段的目标链和建筑揭示同步设计，不能作为一组脱离上下文的高阶词条存在。

第一期推荐映射如下：

| 科技 | 前置 | 主要效果 | 直接联动建筑 |
|------|------|----------|--------------|
| `MaggotBreeding` | 蛆虫阶段已揭示 | 稳定蛆虫生产，确认黑暗资源链成立 | `蛆虫工厂` |
| `NecroticRecycling` | `MaggotBreeding` | 将坏死资源重新导入食物/化学链 | `腐肉育池` |
| `SymbioticHosts` | `NecroticRecycling` | 打开宿主与共生过渡系统 | `共生培育舱` |

映射原则：

1. 每一项科技都必须对应一个玩家能立刻观察到的建筑或资源链变化。
2. 每一项科技都必须是下一项科技的叙事与机制前提。
3. 蛆虫路线必须先完成“资源利用”，再进入“人口异化”。

### 9.1.14 蛆虫科技的显示与揭示规则

蛆虫路线的科技不得在蛆虫阶段揭示前出现在科技树中。即使科技定义已存在，运行时科技列表也必须按阶段过滤。

规则如下：

1. `MaggotBreeding` 在蛆虫阶段正式揭示后才允许显示。
2. `NecroticRecycling` 仅在 `MaggotBreeding` 已研究后进入可见候选。
3. `SymbioticHosts` 仅在玩家完成第一轮黑暗闭环后进入可见候选。
4. `HiveMindProtocol` 与 `CollectiveAwakening` 必须严格后置到更后阶段，不得挤占蛆虫阶段首轮节奏。

## 10.4 工厂生产系统

游戏不再提供独立的合成界面。所有必要的加工资源统一改为通过建筑/工厂持续生产。

### 10.4.1 生产规则

1. 次级资源必须通过对应工厂生产，并持续消耗初级资源。
2. 高级资源必须通过高阶工厂生产，并持续消耗初级资源与次级资源。
3. 玩家获取加工资源的主路径是购买并升级工厂，而不是手动点击合成按钮。

### 10.4.2 设计约束

- 工厂的输入消耗与输出产量都由 Rust 生产系统统一结算。
- 不再保留独立的 crafting tab 作为核心玩法入口。
- T1 基础科技的成本应只依赖初级资源，不能再要求铁锭、芯片等次级/高级资源。
